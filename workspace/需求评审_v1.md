## 一、已确认事实

### 1.1 业务侧
- 客户对外租赁粒度两种：**租一层**、**租单个房间**
- 客户诉求核心：能「一把导入」附件3 的统计表，**不愿逐条建档**
- 全部租赁房源为**外部房产**，非自有
- 客户接受「合同先生效、房间明细后续补」的节奏

### 1.2 系统侧
- 系统语义中的「资产」= 现实生活中的**楼栋**
- 建档顺序：**楼栋 → 楼层 → 房间 → 房间内添加使用人员**（四级）
- 合同**强制关联资产**，且**当前只能选到楼栋级**（不能选楼层/房间）
- **现有台账数据全部为自建**，无租赁数据
- 系统为我方建设，**数据模型可改**

### 1.3 材料侧
- 附件3 .xlsx 是空白模板：13 列 + 1 行示例（"如有多处租赁房屋，请分行填写"）
- 客户实际填报样例（截图）显示字段差异：
  - 多出「**备注**」列
  - 「**租赁建筑面积**」细分为「办公用房㎡、业务用房㎡」两项
- 字段定义以**客户实际填报为准**，按"完整字段集"设计导入
- 4 个受控字典：单位性质（行政/参公/公益一类）、租赁用途、租金来源（财政拨款/自有资金/其他）、备案（是/否）
- 模板缺陷：扩行后 C/G 列下拉校验会丢失

### 1.4 项目约定（2026-09-04 立，至今生效）
- **禁止跨项目联想**：本需求与「神木商铺租赁合同管理」相互独立，不类比、不复用、不互证

## 二、本期范围（做什么）

### 2.1 数据模型改造
- 楼栋实体新增「**取得方式**」字段：自建 / 租用（必填）
- 字段分三组：
  - **共有**（两类均必填）：楼栋名称、地址、层数、用途、建筑面积
  - **自建专属**：产权证号、产权单位、账面价值、用地性质、建成年代、房屋结构
  - **租用专属**：出租方、租期起止、年租金、租金来源、是否备案
- 「取得方式」决定字段显示与校验：
  - 自建不出现租赁字段
  - 租用不出现产权字段（产权类置"不适用"，不进表单）
- **「取得方式」挂楼栋级**（客户答复"先不考虑"混合楼栋场景）
- 房间层沿用既有结构，**不区分自建/租用**

### 2.2 合同侧改造
- 合同关联对象从「楼栋」扩展为「**房间集合**」（一个或多个房间，多对多）
- 关联选择器**单一入口**，不按取得方式分支
- 楼栋/房间不存在时提供**内联新建**入口，不跳出台账模块，建完自动回填关联
- 从合同进入新建时用合同已有信息预填（出租方、租期、租金、用途），避免重复录入

### 2.3 房间批量生成（核心新增能力）
- 提供「**按楼层批量建房间**」：客户输入房间数 + 起始房号 + 面积（平均 或 总面积），系统自动生成
- 整层/整栋租时支持「**先建虚拟单元**」（标"未核实"），后续可拆细为多个房间
- 房间状态机：`未核实 → 已核实`（与客户实际房间清单对齐后切换）

### 2.4 两段式导入机制
- **第一段（导入时刻）**：附件3 每行 →
  - 自动创建 楼栋（取得方式=租用）+ 楼层 + 合同 + 关联 + 租赁总面积
  - 同一行若分办公/业务两类用途，**按用途拆成两组房间占位**
  - 合同**即时生效**
  - 同时**预占房间**（按客户在该层申报的房间数与平均面积生成「未核实」房间占位）
- **第二段（后续补录）**：客户在以下三处补录实际房间清单
  - ① 合同详情页内联录入
  - ② 房间台账模块批量补
  - ③ 「房间明细导入模板」批量导入（附件3 的姐妹表）
- **系统提示机制**（常驻）：
  - 合同详情页 / 楼栋详情页：显示「已分配㎡ / 总租赁㎡」进度条 + 截止期倒计时
  - 台账视图：新增「补录完成度」列，可按未补录筛选
  - 截止期可配（默认 30 天）
  - 超期触发预警，推送给填报单位联系人

### 2.5 兼容存量自建数据
- 自建楼栋（含已有真实房间）与新建租上楼栋（含虚拟占位房间）**共存于同一棵空间树**
- 取得方式=自建的房间保留原房间数据；取得方式=租用的房间初始为「未核实」
- 不动存量自建数据的历史档案字段

## 三、不做什么
- 不处理「一栋楼部分自有、部分租用」场景（取得方式挂楼栋级，混合楼栋下不区分）
- **不改造附件3 .xlsx 模板本身**——导入所需的房间预占信息（每层房间数 + 平均面积）通过系统导入对话框补充
- 不要求客户手工填附件3 的房间明细——房间明细由系统预占 + 客户后续补录
- 不动存量自建数据的历史档案字段
- 不做"公务接待"相关业务（红线）

## 四、待确认问题

| # | 问题 | 影响 | 我的倾向 |
|---|---|---|---|
| Q1 | 房间补录的**截止期默认值**（建议 30 天）与超期预警规则 | 决定两段式兜底强度 | 默认 30 天，超期仅预警不阻塞 |
| Q2 | **未核实房间**是否计入人均面积 / 台账报表？若计入，是否打「未核实」标记？ | 决定首月报表的可用性 vs 准确性 | 计入并打标，不阻塞业务、不掩盖风险 |
| Q3 | 同一行「办公+业务」两类面积，**拆为两个合同** 还是 **一个合同 + 两组房间占位**？ | 决定合同模型与导入逻辑 | 一个合同 + 两组房间占位（按用途分组的房间集合） |
| Q4 | 房间明细补录是否需要**审批流**（填报单位录 → 谁审） | 决定系统复杂度 | 暂不要审批流，切到「已核实」时留填报人+电话痕迹即可 |
| Q5 | 截图与 .xlsx 模板字段差异（备注列、面积分项）**以哪份为准** | 决定导入字段定义 | 以客户实际填报为准（截图反映真实业务） |
| Q6 | 虚拟占位房间「未核实」标记的**长期容差**（默认 30 天 vs 永久） | 决定长期数据治理策略 | 30 天后仍「未核实」的房间从台账隐藏，但保留数据，不阻塞报表 |

## 五、风险

| # | 风险 | 应对 |
|---|---|---|
| R1 | 客户长期不补房间明细，台账脏化、人均面积长期基于估算 | 进度条 + 截止期 + 预警；报表打标 |
| R2 | 同地址重复建楼栋（同名楼栋被多次导入） | 导入前查重：地址 + 出租方模糊匹配，给出「已存在，可能重复」提示 |
| R3 | 自由地址无法稳定解析楼栋/楼层/房间 | 提供地址解析规则模板（正则），人工兜底 |
| R4 | 房间补录由填报单位执行，缺少审核 → 数据质量 | 不上审批流，但「切到已核实」时强制留痕（填报人+联系电话） |
| R5 | 客户要求「一把导入」是体验承诺，但实际数据完整性靠后补驱动 → 可能成为客户二次抱怨点 | 导入成功页明示「哪些待补 + 补录入口」，配操作手册 |
| R6 | 存量自建数据与新增租用数据共存，统计脚本要兼容两种状态 | 报表层加状态过滤；存量脚本不破坏 |
| R7 | .xlsx 模板与客户填报样例字段差异（备注、面积分项）若未对齐，导入会丢列 | Q5 必须先确认，再做导入适配 |
| R8 | 附件3 模板扩行后 C/G 列下拉校验丢失（已记录缺陷） | 改造模板或客户端化录入时必须规避校验丢失 |
